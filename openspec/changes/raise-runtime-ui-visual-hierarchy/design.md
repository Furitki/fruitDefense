## Context

当前主题以 49 个有限语义槽覆盖共用表面、操作、图标、装饰和插画。资源合同已经记录显著 Alpha 光学边界，但所有普通图标仍统一导出为 96×96，再由运行时缩放到不同尺寸；战斗头部实际只有 13 logical px，高清细节被采样丢失。页面层面，Lobby、Battle、Settlement 大量复用同一种米白表面和顶部横幅，代码虽已满足 containment，却没有形成拆包资源所体现的“路由专属组合层”和前中后景明度关系。

本轮只处理表现层。绘制与命中仍由同一权威 layout 生成；BattlefieldProjection、战斗状态、导航和存档不变。普通 WebGL 的 402×874 全屏与代表性 inset 安全区仍是硬验收面。

## Goals / Non-Goals

**Goals:**

- 让战斗头部的阳光、核心、波次在实际显示尺寸下第一眼可辨，并建立可复用的目标尺寸资源合同。
- 让 Lobby、Battle、Settlement 在同一 Sunny Orchard 语言下拥有不同的密度、视觉锚点和纵向节奏。
- 使用一张无文字的竖屏果园景深插画加既有表面/装饰构成背景、内容、前景三层，而不是生成整页截图。
- 将生图结果限定为母版，通过确定性导出和目标像素门禁形成运行时资源。
- 保持此前已经通过的光学居中、快速内缩反馈、按压不越框和 safe-area 行为。

**Non-Goals:**

- 不改变战斗玩法、数值、关卡内容、路由顺序、持久化或输入语义。
- 不复刻或直接发布第三方 APK 的受保护资源；拆包样本仅作为布局和资源规格研究依据。
- 不一次性重画全部 49 个现有槽，也不引入第二套运行时 UI 框架。

## Decisions

### 1. 有限资源合同从 49 槽直接升级到 53 槽

新增 `icon.resource-sun-micro`、`icon.resource-core-micro`、`icon.resource-wave-micro` 和 `illustration.shell-orchard-depth`。不在运行时根据缺槽回退到普通图标；两个生产 ArtSet 必须同时补齐。普通资源图标继续服务 24px 以上场景，micro 资源只服务战斗头部。

替代方案是仅把头部图标从 13px 放大。该方案虽然改善当前截图，但仍保留“一个高清资源承担所有尺寸”的根因，也无法形成可检验的最小尺寸合同，因此不采用。

### 2. Micro 运行时资源按最终 18×18 像素导出

三个 micro 槽可复用各自已审查的高清母版，但必须走独立导出路径：显著 Alpha tight crop、预乘 Alpha 等比缩放、放入 18×18 固定画布、光学居中、清除低 Alpha 毛边。主要剪影占 15～16px，关键笔画在最终图中不得低于 2px，三者二值剪影不得相同或超过规定的 pairwise IoU。

运行时以 18 logical px 绘制该 18px 资源，不再经过 96→13 的大倍率二次缩小。普通图标仍保持 96×96/2x 合同；ArtSet 校验按 `standard` 和 `micro` 两个 tier 分组，而不是强迫两档画布一致。

### 3. 高清生图只拥有竖屏景深母版，不拥有 UI 几何

新增插画只包含低噪声天空、果园中景、路径和下方较深的叶片压边，不包含文字、按钮、边框、图标或状态。生成提示词明确 402×874 目标构图、安全区和三档明度；原始高清输出保存为 source master。导出器采用中心焦点保护的 cover crop 后缩放为 402×874，不让运行时任意拉伸不同宽高比母版。

该插画在 Lobby 与 Settlement 中位于 `surface.safe-area` 之上、所有卡片和文字之下；两条路由使用不同裁切/透明度和内容占用形成各自组合。Battle 不叠加该插画，避免降低棋盘辨识度。

### 4. 路由排版使用“视觉锚点＋重复节奏＋明确收口”

- Lobby：标题为入口锚点；三张关卡卡使用统一的大缩略图、标题/描述基线和选中标记；主按钮紧随卡组，背景景深填补剩余空间但不与卡片争夺焦点。
- Battle：头部增高到 76 logical px；标题、三项 18px micro 指标和两枚同规格控制分为明确组，棋盘上边界同步下移且绘制/命中共用同一投影。
- Settlement：结果横幅与更大的果园插画构成英雄区；三条指标采用同一行高和图标列；主次操作在结果卡后形成清晰收口，避免下方大面积无意义空白。

### 5. 验收优先测最终光栅，不用布局 Rect 自证

Editor 门禁解码最终 PNG，验证 micro 尺寸、Alpha 包络、剪影差异、关键占用和 manifest/ArtSet 一致性。WebGL 门禁在真实 402×874 full/inset canvas 中记录头部图标可见包络、首屏内容占用、背景三层明度、按钮 containment 和 payload identity。手工放大图仅作审查辅助，不作为通过证据。

### 6. 文字承载装饰按有效像素包络定标

`ornament.result-banner` 的运行时画布为 256×72，但显著 Alpha 包络只有 240×32。Settlement 不再把 256×72 透明画布塞进一个名义布局框后直接叠字；布局声明横幅希望得到的可见包络，绘制器根据 ArtBinding 的 `opticalInset` 反推出完整图片绘制矩形。结果标题保持 SectionTitle 字号，横幅有效像素放大到 330×44 logical px，并为最终字形保留内边距。

该规则面向所有承载文字的装饰资源：透明留白不算可用排版空间，不能以缩小文字掩盖装饰包络不足。替代方案是在 exporter 中裁掉透明画布，但这会改变已审查资源的固定宽高合同，并削弱飘带尾部与其他页面的复用，因此本轮选择运行时按光学元数据定标。

### 7. 非交互信息默认无独立表面

`DrawMetric` 表示只读信息而不是按钮、输入或可选项，因此不再绘制 `surface.metric`。战斗头部由 header 承载结构，Settlement 指标由 result card 承载结构；图标、文字、留白和必要分隔负责组织信息。`surface.metric` 仍属于有限美术合同，可供未来明确需要成组强调的结构容器使用，但不再是只读指标的默认绘制路径。

### 8. 强调文字先定字形，装饰资源再适配

结果、章节和状态英雄区的文字是信息主体，横幅只是承载和强化。排版顺序固定为：先确定字体、字重与描边，在最终显示分辨率得到“含描边字形包络”；再读取装饰资源的显著 Alpha 包络；最后按两者和安全边距反推装饰绘制尺寸。禁止先固定图片框，再缩小文字去填剩余空间。

本变更采用以下 402×874 参考光栅约束；其他受支持视口按统一 UI scale 换算，验收仍读取最终截图像素：

- Settlement 的“胜利/失败”等 2～4 字强调文案使用粗体和真实可见描边。含描边字形高度为 28～32 capture px；描边基准厚度为 2 capture px，颜色须与填充和底图形成清晰的两级剪影，不以模糊阴影代替描边。
- 含描边字形高度占横幅显著 Alpha 高度的 52%～64%。上下边距从含描边字形包络量到横幅显著 Alpha 包络，各不小于 8 capture px，二者差值不超过 2 capture px。
- 水平方向至少保留一字宽的平静安全区，折角、叶片、飘带尾部和高对比高光不得侵入文字包络；文案变长时优先加宽横幅或换用已审查的宽版资源，不得把强调文字降到正文层级。
- 描边只用于英雄结果、页面/章节标题或落在复杂插画上的少量强强调文字。正文、补充说明和只读指标不使用粗重描边，也不通过增加独立边框冒充层级。
- 字体、描边和装饰必须作为一个最终光栅整体验收。名义字号、GUI Rect、透明画布尺寸、高清母版预览均不能单独证明通过。

这套约束把“留白”定义为主体已经足够强之后的安全空间：大字与清晰剪影优先，随后保留呼吸感；既不贴边，也不允许小字漂在过大的横幅中央。

## Risks / Trade-offs

- [Risk] 竖屏插画在浅色 UI 后降低文字对比 → 插画限制为低对比中景，内容区继续由不透明/高不透明度表面承载，并在真实截图测对比。
- [Risk] 18px micro 图标过度简化后与大图风格脱节 → 保留同一棕色描边、主色和语义质量块，但删除只在大尺寸成立的叶脉与碎高光。
- [Risk] 增高战斗头部压缩棋盘 → 只从棋盘顶部调出 16 logical px，保持下方控制区和投影一致，并跑完整拖放/命中回归。
- [Risk] 生图输出含白底、棋盘格或微小噪点 → 输出进入审查和显著 Alpha 清理；不能稳定得到透明/干净母版时拒收，而不是在运行时遮盖。
- [Trade-off] 新插画增加 WebGL 纹理体积 → 运行时只保留一张 402×874 无 mipmap、可接受压缩的竖屏资源，构建后复核 payload 增量。
- [Risk] 放大装饰有效像素后透明画布可能超出声明区域 → 反推后的完整图片仍须被所属结果卡容纳，WebGL 验收同时检查有效包络与父容器 containment。
- [Risk] 多次偏移绘制模拟描边可能造成糊边、GC 或不同平台字形差异 → 强调文字描边需要一个明确的共享绘制路径，并以 WebGL 最终光栅而不是编辑器预览验收。

## Migration Plan

1. 新增四个语义槽并一次性更新两个生产 ArtSet、manifest 和运行时导出物。
2. 更新共享绘制 API 与 Lobby/Battle/Settlement 权威布局，删除头部对普通资源槽的旧引用。
3. 增加 Editor 目标像素门禁并重跑聚合 smoke。
4. 构建普通 WebGL，运行 402×874 full/inset 与跨路由状态验收；不通过则回到母版或 layout 修正。

版本控制回退通过撤销本分支提交完成；运行时不包含旧槽位回退逻辑。

## Open Questions

- 本轮先以一张共享竖屏果园景深母版验证页面层级收益；若人工评分仍低于 60，再分别为 Lobby 与 Settlement 生成路由专属母版，而不是提前扩大本次资产面。
