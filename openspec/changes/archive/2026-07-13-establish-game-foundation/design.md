## Context

仓库目前只有 OpenSpec 配置。目标是一个无需后端、打开浏览器即可游玩的单页塔防游戏；后续战斗、经济和装备 change 会并行开发，因此公共状态与文件所有权必须先稳定。

## Goals / Non-Goals

**Goals:**

- 提供可构建、可测试的 React + TypeScript 工程。
- 使用统一坐标、领域类型和纯函数规则支撑确定性游戏更新。
- 让各功能模块能够独立实现并由根组件统一编排。
- 在桌面和移动窄屏上维持参考图的单屏信息层级。

**Non-Goals:**

- 不引入服务端、账号、联网排行或持久化进度。
- 不使用重量级游戏引擎或依赖 Canvas 才能完成的渲染管线。

## Decisions

1. 使用 React、TypeScript 和 Vite。React 负责界面组合，游戏规则保持为 `src/game` 下的纯 TypeScript；相比直接把规则写入组件，更易测试和让多个 change 并行。
2. 游戏空间使用 0 到 100 的归一化坐标，SVG 绘制道路与范围，DOM 绘制可交互实体。这样既能适配响应式布局，又保留标准可访问按钮和拖拽事件。
3. `GameState` 是唯一真相源；`battle`、`economy`、`equipment` 模块导出纯更新函数，`useGameEngine` 负责时钟和动作编排。避免各组件拥有冲突的计时器。
4. 配置与运行实体分离。静态数值进入 `config.ts`，运行态实体使用稳定 id，便于测试、选择与拖拽。
5. 优先使用 CSS、emoji 和矢量形状形成统一的童话果园风格，避免生成资产阻塞功能验收；后续可以无损替换为精灵图。

## Risks / Trade-offs

- [大量 DOM 实体可能影响性能] → 同屏僵尸与投射物设置上限，并以单一 animation frame 批量更新。
- [并行 change 争用核心状态文件] → foundation 固定类型和模块签名，子 change 只拥有各自模块与组件，根集成由主 agent 完成。
- [触摸拖拽与页面滚动冲突] → 游戏舞台设置明确触控区域，并提供点击选择后再点击目标的等价操作。
