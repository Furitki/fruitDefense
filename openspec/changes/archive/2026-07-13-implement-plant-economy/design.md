## Context

经济和操作模块连接苗圃、战场植物与战斗事件。完整规则要求以拖拽为主，同时 WebApp 必须照顾鼠标、触摸和键盘用户。

## Goals / Non-Goals

**Goals:**

- 实现可持续的刷新、布阵、合成、出售和生产循环。
- 所有操作在执行前提供合法性反馈，错误操作不丢失实体。
- 让随机结果可测试，且首批不会出现无法战斗的软锁。

**Non-Goals:**

- 不做卡池解锁、局外货币或付费刷新。
- 不实现复杂背包排序。

## Decisions

1. 使用带种子的伪随机入口生成苗圃批次，首批先抽取至少两株攻击植物，再补齐随机位置，最多两株向日葵。
2. 拖拽载荷只传稳定实体 id 与来源；最终规则由经济模块重新校验，避免 UI 伪造合法操作。
3. 提供点击选择再点击目标的等价流程，既支持触摸/键盘，也便于自动化验收。
4. 经济来源包含向日葵、击杀、波次奖励和出售返还；刷新价格为 10、15、20 后持续每次加 5。
5. 植物移动保留内部计时状态，合成在目标格完成并重置攻击目标；战斗中移动后仅移动操作冷却两秒。

## Risks / Trade-offs

- [随机批次导致不可重复问题] → 将随机源封装并对约束进行单元测试。
- [原生拖拽在触摸端不一致] → 以 pointer events/点击落点为主，HTML drag 只作桌面增强。
- [经济失衡导致死局] → 保证击杀与波次收入，并在无法清空苗圃时始终允许出售。
