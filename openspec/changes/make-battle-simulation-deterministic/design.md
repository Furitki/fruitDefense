## Context

`GameSimulation.Tick` currently executes gameplay once for every render-frame callback, clamps each callback to 0.05 seconds, and multiplies that variable duration by the selected speed. Its `System.Random` is constructed once, so `Reset(seed)` changes the public seed field without restoring the random sequence. The runtime host already supplies unscaled frame time and must continue compiling unchanged.

The deterministic boundary must remain scene-independent and WebGL-compatible. It must not introduce threads, external packages, presentation dependencies, content-catalog changes, or project-setting edits.

## Goals / Non-Goals

**Goals:**

- Advance all battle rules in exact 0.05 second logical steps.
- Make different render-frame partitions produce the same result when they represent the same accepted time.
- Express 2x speed as additional fixed steps rather than a larger logical-step duration.
- Make the random algorithm and its complete state explicit, serializable, seedable, and replayable.
- Preserve `Tick(float)` as the existing runtime entry point while exposing frame, step, and accumulator operations.

**Non-Goals:**

- Preserving the exact sequence generated by `System.Random` for a historical seed.
- Adding a full battle snapshot, command log, content version, or replay-file format.
- Changing game balance, UI, application routing, maps, content authoring, scenes, or project settings.
- Automatically simulating discarded time after a long stall.

## Decisions

### Use a bounded fixed-step accumulator

`GameSimulation` exposes `AdvanceFrame(float)`, `Step()`, and `ResetFrameAccumulator()`. The accumulator uses `double` so repeated small render deltas do not lose a logical step through float rounding. A logical step is always 0.05 seconds.

`AdvanceFrame` rejects negative and non-finite input as zero, clamps accepted real-frame time to 0.25 seconds, multiplies it by the current 1x/2x speed, then caps pending simulation time at 0.25 seconds. It consumes at most five steps and returns the number consumed. Capping the pending time deliberately drops excess stall time rather than creating a catch-up debt that leaks into later frames.

Multiplying accumulator input was selected over multiplying the duration passed into gameplay. It preserves cooldown, projectile, damage-over-time, spawn, and collision ordering at both speeds. A variable final remainder step was rejected because it would reintroduce frame partition dependence.

`Tick(float)` delegates to `AdvanceFrame(float)`. Direct `Step()` is available to deterministic tools and advances exactly one logical step only when the simulation is not paused or terminal. Paused and terminal frame callbacks clear pending time, preventing a later unpause or route change from advancing stale time.

### Use xorshift32 with explicit state

A small `[Serializable]` `DeterministicRandom` owns a public-readable 32-bit state. Its algorithm is fixed to xorshift32 (`x ^= x << 13; x ^= x >> 17; x ^= x << 5`) and supplies bounded integer and unit-interval values needed by the simulation. All shuffle and nursery decisions use this source.

The integer seed is converted with an unchecked bit-preserving cast. Seed zero maps to the fixed non-zero state `0x6D2B79F5`, because zero is the absorbing state of xorshift32. Restoring a zero state uses the same mapping. Modulo selection is accepted for the current small gameplay ranges; exact algorithm stability is more valuable here than introducing rejection-loop variability.

`Reset(seed)` resets the model, accumulator, and random source before initial flowerpots are shuffled. The public state retains the requested integer seed while the random source exposes the actual mapped state. Time-based implicit seeding is removed so a default construction is reproducible.

### Validate state rather than presentation

An independent editor smoke constructs scene-free simulations and calculates a canonical checksum from deterministic gameplay state, excluding feedback text/color and other presentation-only data. It verifies identical command replay, render-delta partition equivalence, speed equivalence, and reset replay including initial flowerpot and nursery random outcomes.

The existing project smoke contains assumptions that a sub-0.05 `Tick` executes immediately. This change intentionally moves those actions to the next fixed-step boundary; those assertions should use `Step()` or accumulate a full step when the root integration task updates shared validation.

## Risks / Trade-offs

- [A frame stall discards more than 0.25 simulated seconds, especially at 2x] → This is intentional spiral-of-death protection; future session telemetry can record dropped time without changing deterministic state.
- [Existing tests expect an action after one 0.01 second callback] → Provide `Step()` for exact test setup and document the one-fixed-step timing boundary for root integration.
- [Changing from `System.Random` changes seeded initial layouts] → Treat xorshift32 output as the new versioned baseline and validate reset/replay stability, not legacy sequence identity.
- [Floating-point operations can still differ across architectures] → Fixed ordering removes frame partition variance; cross-architecture bitwise replay remains outside P0 and can later use quantized snapshot checks.

## Migration Plan

1. Add and validate the deterministic random source in isolation.
2. Replace all simulation random calls and make reset reseed before initial-state generation.
3. Extract the old `Tick` body into one fixed `Step` and add bounded frame accumulation.
4. Run the dedicated deterministic editor smoke, Unity compilation, and the existing smoke to identify shared assertions that require root-integration adjustment.
5. Roll back by reverting this isolated change; no save data or project settings are migrated.
