# 待录入审核设计

本文用于暂存尚未获得确认、不能写入正式策划案的设计方案。这里的内容均为候选设计，不代表已定规则，也不覆盖 [游戏策划总纲](game-design-overview.md)。

每项候选设计经过人工审核后才能进入正式策划文档：

- `待审核`：仅记录方案，不能作为正式策划结论。
- `已确认待录入`：用户已明确批准，可以同步到对应正式章节。
- `已录入`：已经按用户确认同步到正式策划文档，本文仅保留审核与决策记录。
- `已撤回`：保留决策痕迹，但不再推进。

## 地图编辑器：分层地貌绘制交互简化

- **状态**：已撤回
- **撤回原因**：该方案只简化了地貌素材与 Dual-Grid 组合的绘制入口，没有编辑版本化地图聚合中的玩法格、路线和点位，也没有地图边界、完整性校验、目录导出或真实战斗预览。它应被定位为地貌素材实验室，不能作为地图编辑器的正式方案。
- **目的**：让地图绘制者不需要理解 `A`、`B`、前景、背景、TileSet 或 Mask 等实现概念，就能完成纯底图、分层地貌和双向组合绘制。
- **正式文档影响**：若审核通过，预计同步到 `docs/design/game-design-overview.md` 的“内容生产与版本边界”，用于补充地图内容制作入口的长期方向。
- **实施规划**：由 OpenSpec change `simplify-layered-terrain-editor-workflow` 单独约束；在该 change 实施前，本节不代表编辑器已经具备下述交互。

### 候选主流程

地图绘制入口提供四个带材质缩略图的快捷笔刷：

| 绘制者看到的笔刷 | 写入结果 |
|---|---|
| 纯草地 | 草地底图，并清除该格的地貌和精修边缘 |
| 纯泥土 | 泥土底图，并清除该格的地貌和精修边缘 |
| 草覆泥土 | 泥土底图＋草地地貌 |
| 泥覆草地 | 草地底图＋泥土地貌 |

只有包含地貌的笔刷才显示边缘选项：

- **基础边缘**：只使用通用地貌轮廓。
- **AI 精修边缘**：使用已经生成并审核过的定向边缘素材；绘制时不实时调用 AI，也不使用脚本修改像素边缘。

当前笔刷应始终显示为面向绘制者的摘要，例如“草覆泥土／AI 精修边缘”。从统一的地图工具入口打开绘制器后，自动定位当前地图并进入明确的绘制状态，不要求使用者在 Project 面板中寻找 TileSet 资源。

### 候选高级流程

以下操作默认折叠，只在需要精确修改单层时展开：

- 只绘制草地或泥土地貌，保留格子中已有底图。
- 只擦除地貌和对应边缘，保留底图。
- 清空整个格子，同时移除底图、地貌和边缘。
- 查看底层逻辑 Tilemap、生成输出、标记 Tile 与 TileSet 绑定；这些属于开发者设置，不进入日常绘制主流程。

在空白格上尝试“只绘制地貌”时，应提示先绘制底图。某个方向缺少 AI 精修素材时，应禁用该选项并说明原因，不能拿反方向素材替代，也不能静默切换成其他边缘。

### 候选扩展原则

界面名称、缩略图和色块最终应来自地貌材质配置，而不是在工具中写死“草地”和“泥土”。未来增加水面、雪地或其他材质时，继续复用“一层底图＋一层可选地貌”的约束，同时隐藏内部 `A/B` 身份。

### 待审核结论

- 不再采用“四个快捷组合＋折叠高级分层操作”作为完整地图编辑器的正式交互。
- 四个快捷组合、AI 精修边缘和 Mask 验收板仅保留在地貌素材实验室中，服务美术与渲染验证。
- 是否将地貌素材实验室作为独立开发工具长期保留，随新的正式地图编辑器一起审核。

## 关卡地图编辑器：版本化地图聚合的一站式制作流程

- **状态**：已录入
- **目的**：让关卡设计者不修改代码、不操作原始 TileSet、不维护第二套坐标，即可从空白地图完成玩法拓扑、路线、点位、地貌表现、校验、实战预览和目录发布。
- **录入位置**：已同步到 `docs/design/game-design-overview.md` 的“4.3 关卡差异与待定战斗问题”和“6.1 地图制作与发布流程”。
- **实施规划**：具体行为与验收继续由 OpenSpec change `build-canonical-battlefield-map-editor` 单独约束；本文仅保留设计审核记录。

### 已确认产品边界

地图制作拆分为两个互不冒名的工具：

1. **地貌素材实验室**：维护底图、透明地貌、定向精修边缘和十六种 Dual-Grid Mask 验收板；允许孤岛、孔洞和对角测试，不生成可玩关卡。
2. **关卡地图编辑器**：编辑一个有固定尺寸和稳定 `mapId` 的版本化地图聚合；统一管理表现布局、玩法拓扑、路线和类型化点位，并导出给关卡目录使用。

地貌素材实验室不得出现在普通关卡制作主流程中，也不得把素材验收板作为地图可用性的证据。

### 已确认主流程

`新建/打开地图 → 设置身份与尺寸 → 绘制玩法拓扑 → 编辑路线与点位 → 绘制地貌表现 → 完整校验 → 实战预览 → 发布到关卡目录`

- **身份与尺寸**：创建稳定 `mapId`、正数网格宽高和单位格尺寸；创建时自动为所有格子写入默认底图，画布外禁止落笔。
- **玩法拓扑**：绘制有限、已审核的种植、敌人通行、玩家通行和碰撞能力；不得由地貌图片反推玩法合法性。
- **路线与点位**：用有序相邻格编辑主路线，自动显示方向、入口和出口；配置刷怪点、路线目标、核心和初始花盆候选组，并使用稳定 ID。
- **地貌表现**：在同一有界二维画布上绘制底图、可选地貌和可选定向边缘；支持单格、矩形、区域填充和吸管。Mask 由语义布局自动推导，策划不逐格选择 Mask。
- **协作辅助**：允许显式执行“按玩法拓扑生成推荐表现”，例如把路线建议为石板、可种植区建议为草地；该操作是可撤销的批量写入，不建立表现层对玩法层的运行时权威。
- **校验与发布**：无效草稿可以保存，但缺失覆盖、越界、路线断裂、必需点位缺失、同格冲突、未知能力或材质引用缺失时，禁止实战发布并定位到具体格子或对象。正式发布集合由单独的发布清单管理；运行时生成物只能从该清单全量重建，不作为可手工编辑或反向读取的第二份真相。
- **预览**：编辑器内预览和 Battle 实战预览都使用正式 `BattlefieldProjection` 与编译结果，不使用透视 Scene 视图或独立演示板作为最终效果依据。

### 已确认交互原则

- 主界面按“玩法、路线与点位、表现、校验”组织，不暴露 `A/B`、Mask、逻辑 Tilemap、生成输出或资源 GUID。
- 所有绘制工具受地图边界约束；悬空格、无限画布落笔和缺失底图不是合法作者状态。
- 当前层、选中工具、笔刷范围、坐标、错误数量和发布状态始终可见。
- Undo/Redo 以一次完整手势或一次批量操作为单位；矩形、填充和自动建议必须整体可撤销。
- 表现与玩法允许有意不同，但编辑器对可疑差异给出警告，不自动篡改另一层。
- 精修边缘按材质对和连续区域应用；缺少确切方向素材时明确禁用，不反向借用或静默降级。
- 编辑画布按所选模板关卡的真实主题和 `BattlefieldTerrainPalette` 解析地貌；缺失底图、地貌或确切方向边缘时显示阻塞诊断，不以占位色块伪装成功。

### 已确认验收门槛

- 从空白资产开始，仅使用正式地图编辑器创建一张新地图；全过程不修改 C#、不打开原始 TileSet、不手工编辑生成 Tilemap。
- 保存并重新打开后，地图身份、尺寸、三层内容、路线顺序、点位 ID 和校验结果一致。
- 越界绘制被拒绝；空底图、断裂路线、缺失核心、无效点位和未知引用均能阻止发布并定位原因。
- 校验通过的地图可编译进入关卡目录，在正式 Battle 场景中完成刷怪、寻路、种植、核心受击和结算流程。
- 正式 Playtest 必须先从发布清单全量重建生成资源，再重新装配正常关卡目录并按稳定 `levelId` 启动；临时内存预览不能替代发布验收。
- 编辑器预览与运行时在地貌、路线、点位和投影位置上保持一致；地貌素材验收板不得替代此项证据。
- 自动化验收至少覆盖新建、编辑、撤销、保存重开、编译、负例门禁和 Battle 集成；人工验收必须包含完整编辑器画面与真实竖屏战斗画面。

### 审核结论

- 采用“地貌素材实验室＋正式关卡地图编辑器”的双工具边界。
- 采用“玩法拓扑优先、表现随后、显式建议但不反向授权”的制作顺序。
- 允许保存无效草稿，但严格禁止无效地图进入关卡目录和正式实战预览。
- 以“无需改代码制作一张新可玩地图”为地图编辑器完成的最低验收标准。
